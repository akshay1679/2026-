- Collection of digital evidence
    
- ❌ Do NOT investigate on real/original evidence
    
- ✅ Always create **replica (forensic copy)** of storage
    
- <mark style="background: #ABF7F7A6;">Investigation is done on the **copy only**</mark>

# 🧪 **REPLICA & HASHING**

### 🔸 Replica

- Exact copy of original evidence
    
- Used for analysis/investigation
    
- Original evidence remains untouched
    

### 🔸 Hash Value (Integrity Check)

- Original device hash → `abc123`
    
- Replica hash → `abc123`
    
- ✅ Same hash = data unchanged
    

### 🔸 During Investigation

- Work only on replica
    
- Generate new hash after analysis
    
- Compare with original hash for integrity

# 🔍 **Digital Forensics: Acquisition (Detailed Notes)**

## 1. 📌 What is Acquisition?

- **Acquisition** = Process of collecting **real evidence** from a device.
    
- Instead of working on the original evidence, we:
    
    - Create a **replica (forensic copy)** of the storage.
        
- Purpose:
    
    - Preserve original evidence
        
    - Maintain integrity
        
    - Enable safe investigation
        

---

## 2. 💻 Device Context (Example Scenario)

- Device: Laptop used in a cyber attack (e.g., insider threat)
    

### Device Ownership Types:

- **Personal Device (PII involved)**
    
- **CYOD (Choose Your Own Device)**
    
- **COBO (Corporate Owned, Business Only)**
    
- **COPE (Corporate Owned, Personally Enabled)**
    

---

## 3. 🔐 Hashing (Integrity Verification)

- A **hash value** is a digital fingerprint (e.g., `abc123`)
    

### Steps:

1. Generate hash of **original device**
    
2. Create **forensic copy (replica)**
    
3. Generate hash of **replica**
    
4. Compare hashes:
    
    - ✅ Same → Integrity maintained
        
    - ❌ Different → Evidence tampered
        

### Used in:

- Investigation
    
- Court/Jury presentation
    

---

## 4. ⚠️ Challenges in Acquisition

### Memory Types:

- **Volatile Memory**
    
    - Temporary (RAM)
        
    - Lost when system is OFF
        
- **Non-Volatile Memory**
    
    - Permanent (HDD, SSD)
        
    - Remains after reboot
        

---

## 5. 🔌 Importance of Power State

1. **System ON**
    
    - Can capture RAM (important evidence)
        
2. **System OFF**
    
    - RAM data lost
        
3. **Sudden Shutdown**
    
    - Data corruption possible
        
4. **Normal Shutdown**
    
    - Some traces may be erased
        

---

## 6. 🧠 Order of Volatility (Most → Least Volatile)

1. **CPU Registers & Cache**
    
    - Temporary process data
        
2. **Routing Table, ARP Cache, Process Table**
    
3. **RAM (Main Memory)**
    
    - Running processes
        
    - Network connections
        
    - Malware (fileless)
        
4. **Temporary File Systems / Swap Space**

## 12. ⚖️ Methods of Disk Acquisition

## 🔹 1. Logical Copy (Simple Copy)

- Copies only **active files**
    
- Faster
    
- Less reliable for forensics
    

### Limitations:

- ❌ No deleted files
    
- ❌ No slack space
    
- ❌ Partial metadata
    

---

## 🔹 2. Bit-by-Bit Copy (Forensic Image)

- Copies **entire storage**
    
- Includes:
    
    - Deleted files
        
    - Slack space
        
    - Full metadata
        

### Advantages:

- ✅ Forensically sound
    
- ✅ Court admissible
    
- ✅ Complete data
    

### Disadvantages:

- ❌ Slower
    
- ❌ Larger storage required
    

---

## 13. 📊 Logical vs Forensic Imaging (Quick Comparison)

|Feature|Logical Copy|Bit-by-Bit Copy|
|---|---|---|
|Scope|Active files only|Entire disk|
|Deleted Files|❌ No|✅ Yes|
|Slack Space|❌ No|✅ Yes|
|Metadata|Partial|Full|
|Speed|Fast|Slow|
|Legal Use|Weak|Strong|
|Verification|No|Hash-based|

---

## 14. 🧪 Key Forensic Concepts

- Always work on **copy, not original**
    
- Maintain **chain of custody**
    
- Use **hash verification**
    
- Prefer **bit-by-bit imaging** for legal cases
    

---

## 15. 🧾 Final Workflow Summary

1. Identify device
    
2. Check power state
    
3. Capture volatile data (RAM)
    
4. Generate initial hash
    
5. Create forensic image
    
6. Generate new hash
    
7. Compare hashes
    
8. Analyze image
    
9. Present report
